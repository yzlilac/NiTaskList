# NiTaskList

这个练习是一份「小任务清单」。你可以添加任务、勾选完成、按状态筛选和删除。登录后，任务保存在账号下。换浏览器时，登录同一个账号即可继续查看。访客模式的清单与当前浏览器关联，退出登录后可以回到该浏览器的访客清单。

## 第一课　在 Mac 上跑起来

打开 Mac 的「终端」，进入 `NiTaskList` 项目文件夹，再按顺序运行下面三行。首次安装依赖需要联网。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/waitress-serve --listen=127.0.0.1:8080 --call app:create_app
```

最后一行显示 `Serving on http://127.0.0.1:8080` 后，在浏览器打开 [小任务清单](http://127.0.0.1:8080)。`127.0.0.1` 是当前电脑的地址。如果已打开过本地预览，可以先访问页面。自己在终端启动时，要保持终端打开，按 `Ctrl+C` 可以停止服务。以后再启动时，进入项目文件夹后执行最后一行即可。

亲自做一遍这四步。

1. 添加「学习 Codex」。列表里应出现一行新任务。
2. 勾选任务。标题会划线，已完成的数量会增加。
3. 刷新浏览器。刚才的任务和勾选状态应继续显示。
4. 切换到「已完成」并删除刚才的练习任务。再次刷新，确认它已消失。

要验证账号功能，先在普通窗口注册并登录，添加一条任务并勾选完成。再用无痕窗口打开同一个地址，登录同一个账号，确认能看到这条任务及其完成状态。换用另一个账号时，会看到该账号自己的清单。

要练习导入，先退出登录，添加一条访客任务并勾选完成。用同一个浏览器登录，核对页面显示的接收账号，再点「导入访客任务」。确认原有账号任务仍在，导入的任务也保留了完成状态。刷新后，每条任务只出现一次。

## 第二课　跟着一项任务读代码

| 环节 | 文件 | 点击「添加任务」后发生了什么 |
| --- | --- | --- |
| 前端页面 | `templates/index.html`、`static/style.css` | HTML 放置输入框和按钮，CSS 决定它们的样式。 |
| 前端逻辑 | `static/tasks.js` | 读取输入框里的文字，用 `POST /api/tasks` 发出添加请求。 |
| 后端 | `app.py` | Flask 把请求交给 `add_task()`。它检查内容长度，再把任务写入数据库。 |
| 数据库 | `instance/tasks.sqlite3` | SQLite 把任务保存在磁盘上。刷新时，浏览器发送 `GET /api/tasks`，后端再把数据读出来。 |

`/api/tasks` 是前端和后端约定的地址，也叫 API。页面和 API 由同一个 Python 服务提供。`instance/tasks.sqlite3` 会在第一次启动时自动创建。

## 第三课　给 Codex 一个小需求

这次 Codex 已经把第一个版本搭好了。你可以用下面这条指令练习如何指挥它。修改很小，结果立刻能从页面看出来。

> 请把首页标题从「小任务清单」改成「我的学习清单」，标签页标题也一起改。告诉我修改了哪个文件，运行项目，在浏览器刷新并确认两个标题都正确。用我能听懂的话解释这次改动。

以后可以沿用这个顺序。先说清楚谁要做什么，再告诉 Codex 怎样算做对，最后让它实际运行并核对。比如，要加「修改任务名称」，就明确说「从列表改名，刷新后保留新名称，已完成状态继续保留」。这项改动会同时涉及页面、API 和数据库。

在 Codex 中，打开项目文件夹后可以直接用自然语言交代目标和验收条件。另开项目时，先选它的文件夹，再开始对话。[OpenAI 官方快速入门](https://learn.chatgpt.com/docs/quickstart)

## 第四课　把同一份程序搬到腾讯云

本机运行时，浏览器只需找这台 Mac。部署时，我们把代码放到腾讯云服务器，让服务在退出终端后也继续运行，再给浏览器设置一个能到达它的入口。执行前先从腾讯云实例详情确认系统、地域和登录方式。[腾讯云部署与验收步骤](deploy/README.md)
